LightSync v2 — Technical Product Specification

Project: LightSync v2
Type: Standalone AI-powered music interaction and visualization application
Primary Platform: Desktop
Prototype Hardware: M5Stack Core + WS2812B LED strip + MIDI keyboard
Development Target: RMK Innovate Hackathon 2026
Document Status: Prototype / PoC Specification
Version: 2.0

1. Product Overview
1.1 Vision

LightSync is a unified music interaction platform that connects music input, visual feedback, physical LED lighting, learning, performance analysis, and AI assistance into a single application.

The core concept is:

One music event. Many experiences.

A single musical event—such as a MIDI note being played—can simultaneously drive:

Physical LED feedback
On-screen visualization
Learning guidance
Performance tracking
Game mechanics
Music analysis
AI coaching

LightSync is designed to move beyond being a simple MIDI-to-LED controller and become a music interaction platform.

2. Primary Objectives

The prototype should demonstrate the following capabilities:

Receive MIDI input.
Interpret musical events in real time.
Maintain a centralized music/keyboard state.
Display responsive visual feedback.
Control a physical WS2812B LED strip.
Run LED effects locally on the M5Stack.
Provide configurable visual effects.
Provide a learning/practice experience.
Record performance information.
Generate performance analytics.
Provide AI-assisted coaching.
Present everything through a polished standalone desktop application.
Maintain low-latency real-time interaction.
Avoid unnecessary dependency on cloud services for core functionality.

The web technology is therefore an internal UI technology, not a separate website.

17. LED Rendering Architecture

The PC should not continuously transmit every LED's RGB value.

Avoid:

PC
 ↓
LED 1 RGB
LED 2 RGB
LED 3 RGB
...
LED 144 RGB
 ↓
M5Stack

Instead:

PC
 ↓
Semantic command
 ↓
M5Stack
 ↓
Local Effect Engine
 ↓
LEDs

Example conceptual commands:

NOTE_ON
START_EFFECT
SET_THEME
SET_BRIGHTNESS
SET_SCENE

This reduces communication overhead and allows the M5Stack to independently animate the LEDs.

26. AI Architecture

AI should not be placed in the real-time music/LED path.

Bad architecture:

MIDI
 ↓
AI API
 ↓
Response
 ↓
LED

This introduces latency and makes the system unreliable.

Instead:

MIDI
 ↓
Event Bus
 ├── Visualizer
 ├── LED
 ├── Learning
 └── Analytics
          │
          ▼
      AI Layer

The AI operates asynchronously.

27.2 LLM AI

AI Coach

Input:

Frequent mistakes

Output:

Example:

The AI should interpret LightSync-generated performance data, rather than inventing measurements.

28. AI Visual Copilot

AI produces a structured effect configuration conceptually containing:

The LightSync engine then validates and applies the configuration.

The AI should never directly generate individual LED frames.

Conceptually:

38. Core Design Principles
Principle 1 — One Event, Many Experiences

Every important musical event should flow through the common event system.

Principle 2 — Real-Time Path Must Be Deterministic

MIDI → visualization → LED should not depend on an LLM or cloud service.

Principle 3 — Render Locally

The browser renders its own animation.

The M5Stack renders its own LED animation.

Neither should receive unnecessary frame-by-frame data.

Principle 4 — Semantic Communication

Send:

"Note C4"
"Start Ripple"
"Brightness 80%"

rather than:

144 RGB values × 60 frames/sec
Principle 5 — AI Assists, It Doesn't Control the Core

AI interprets music/performance data and generates recommendations/configurations.

It should not sit inside the latency-sensitive music path.

Principle 6 — Local First

The application should remain useful without internet access.

Principle 7 — Hardware Independence

The PC should communicate with a device abstraction rather than directly coupling the entire application to one specific controller.

Principle 8 — Effects Are Data-Driven

Effect parameters should be configurable without firmware recompilation.

40. Prototype Success Criteria

The prototype can be considered successful when the following complete flow works:

1. Launch LightSync
        ↓
2. M5Stack connects
        ↓
3. MIDI keyboard connects
        ↓
4. User presses a key
        ↓
5. LightSync generates NOTE_ON
        ↓
6. UI reacts immediately
        ↓
7. Canvas animation plays
        ↓
8. M5Stack receives semantic event
        ↓
9. LED effect plays
        ↓
10. User changes effect in Effect Studio
        ↓
11. Physical LED behavior changes
        ↓
12. User enters Learning Mode
        ↓
13. LightSync tracks performance
        ↓
14. Analytics are generated
        ↓
15. AI Coach interprets the results
        ↓
16. User receives personalized feedback

That is the complete LightSync v2 PoC story.

The architecture in one sentence

LightSync is a standalone Python-powered desktop application with an embedded React/TypeScript interface, GPU-accelerated visualizer, centralized music event architecture, AI-assisted music intelligence, and an M5Stack-based physical lighting runtime controlling WS2812B LEDs.
